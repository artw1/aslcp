ASLCP GitHub

A web control panel for your AllStarLink 3 node

ASLCP lets you connect, monitor and manage favorites with live status from any browser, and it can set up digital modes for you. It runs on Debian 12 (bookworm), Debian 13 (trixie) and Raspberry Pi OS (arm64 and amd64; 64-bit only).

  • Latest release 2.3.1
  • Latest beta 2.4.0

Docs, screenshots and bug reports are on GitHub.

Quick install

Run this on the node (over SSH or in a terminal):

curl -fsSL https://w1jar.github.io/aslcp/install.sh | sudo sh

Run this on the node (over SSH or in a terminal). It works on an ASL3 card or on plain Debian or Raspberry Pi OS Lite 64-bit: if ASL3 is not installed, the installer installs it first (asl3 and asl3-menu; a few minutes, many packages).

On a freshly flashed ASL3 card, wait for its first-boot setup and reboot (20-30 minutes) before you install. The installer checks this.

At the end the installer prints a one-time setup link. Open it to create the administrator or to restore a backup from an existing node. sudo aslcp admin setup-code shows the code again.

Install options

Pick what you need and copy the command. Everything is optional.

Digital modes
ASL3 telemetry
Port 80 and other ASL web services
Web port

1024-65535, or 80; 8080 is the default. Avoid 9090 (Cockpit on ASL3). Port 80 is set for you by the option above.

Channel

Your command

curl -fsSL https://w1jar.github.io/aslcp/install.sh | sudo sh

Add these before sh, after sudo, separated by spaces. All are optional:

ASLCP_ASL3=0
Do not install ASL3 (no and false work too). By default the installer installs asl3 and asl3-menu if they are missing. ASLCP_ASL3=1 fails instead of continuing when ASL3 is not available for the system.
ASLCP_DV=1
Also enable digital modes (yes and true work too).
ASLCP_PORT=8181
Web port, 1024-65535, or 80. The default is 8080. Avoid 9090 (Cockpit on ASL3).
ASLCP_TAKEOVER=1
Run ASLCP on port 80 and turn off the other ASL web services (yes and true work too). See below.
ASLCP_ASL_TELEMETRY=0
Turn off ASL3 telemetry, the anonymous usage report ASL3 sends to AllStarLink every day, and mask it (off, no and false work too). ASLCP_ASL_TELEMETRY=1 turns it back on (on, yes and true work too). By default it is left as ASL3 ships it (on).
ASLCP_CHANNEL=beta
Use the beta channel (new builds before they are promoted to stable). The default is stable.

Example with several options:

curl -fsSL https://w1jar.github.io/aslcp/install.sh | sudo ASLCP_DV=1 ASLCP_PORT=8181 ASLCP_CHANNEL=beta sh

ASLCP on port 80, no other ASL web UI

An ASL3 image runs Apache, Allmon3 and its own web UI next to ASLCP. To make ASLCP the only web UI, on port 80:

curl -fsSL https://w1jar.github.io/aslcp/install.sh | sudo ASLCP_TAKEOVER=1 sh

The installer stops and disables Allmon3, the web server of the ASL web UIs (Apache, lighttpd or nginx), asl-web-ui and Supermon, but only those that exist and are on, and lists each one. Asterisk and app_rpt keep running. Nothing is uninstalled. Then ASLCP moves to port 80 and the panel is at http://your-node/. If something else still holds port 80, the installer names it and leaves ASLCP on its old port.

To undo it (ASLCP goes back to its old port and the units it turned off are enabled and started again):

curl -fsSL https://w1jar.github.io/aslcp/install.sh | sudo ASLCP_TAKEOVER=undo sh

Changing things later

Web port

The web interface listens on port 8080 by default. To change it, run the installer again with ASLCP_PORT (1024-65535, or 80), or edit listen in /etc/aslcp/aslcp.conf (for example listen = :8181) and run sudo systemctl restart aslcp. The installer warns if another program already uses the port.

If firewalld is running, the installer and the package open the configured port for you. With another firewall (ufw, nftables, a router) open the TCP port yourself. If you edit listen by hand while firewalld is running, open the new port too.

Digital modes

Run sudo aslcp dv enable, or use Settings, Digital Modes, in the web UI. If enabling fails during the installer, the installer still finishes and you can retry with this command.

Update

Use Settings → Updates in the web UI, or:

sudo apt update && sudo apt upgrade

Uninstall

sudo apt remove aslcp   # keeps users and favorites
sudo apt purge aslcp    # also deletes them

apt purge also deletes the config history and ASLCP's digital modes state (which holds copies of network passwords). Your Asterisk config stays.

Manual apt setup

Prefer not to pipe a script? Add the signed repository yourself:

sudo curl -fsSL -o /usr/share/keyrings/aslcp-archive-keyring.gpg https://w1jar.github.io/aslcp/aslcp-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/aslcp-archive-keyring.gpg] https://w1jar.github.io/aslcp stable main" | sudo tee /etc/apt/sources.list.d/aslcp.list
sudo apt update && sudo apt install aslcp

Signing key fingerprint: 9BA6A82745D8B69A9812848FAB83EBF1976B5855 (armored key)

Beta channel

Every new version goes to the beta suite as soon as it is built. It becomes a release (suite stable) when it is promoted after testing: the same package, not a rebuild. The beta suite also carries every release, so beta users are never behind. Betas may be less stable.

To use it, put beta instead of stable in the line above:

echo "deb [signed-by=/usr/share/keyrings/aslcp-archive-keyring.gpg] https://w1jar.github.io/aslcp beta main" | sudo tee /etc/apt/sources.list.d/aslcp.list

Or install with ASLCP_CHANNEL=beta (see the options above), or switch in Settings → Updates in the web UI. It is the same setting: it changes the suite in /etc/apt/sources.list.d/aslcp.list. Going back to stable does not downgrade: the node stays on the installed version until a release newer than it is promoted.
